NORMATIVE INTERNAL ALGORITHMS
======================================================================

--------------------------------------------------
Algorithm 16: ML-KEM.KeyGen_internal(d,z)
--------------------------------------------------

Input:
- d: exactly 32 bytes
- z: exactly 32 bytes

Operation:

  (ekPKE, dkPKE) = K-PKE.KeyGen(d)

  ek = ekPKE

  dk =
      dkPKE
    || ek
    || H(ek)
    || z

Outputs:
- ek: 1184 bytes
- dk: 2400 bytes

--------------------------------------------------
Algorithm 17: ML-KEM.Encaps_internal(ek,m)
--------------------------------------------------

Inputs:
- ek: exactly 1184 bytes
- m: exactly 32 bytes

Operation:

  h = H(ek)

  g_input = m || h

  (K,r) = G(g_input)

  c = K-PKE.Encrypt(ek,m,r)

Outputs:
- K: first 32 bytes of G output
- c: 1088 bytes

The second 32 bytes of G output are r.

Do not swap K and r.

--------------------------------------------------
Algorithm 18: ML-KEM.Decaps_internal(dk,c)
--------------------------------------------------

Inputs:
- dk: exactly 2400 bytes
- c: exactly 1088 bytes

Parse:

  dkPKE = dk[0:1152]
  ekPKE = dk[1152:2336]
  h     = dk[2336:2368]
  z     = dk[2368:2400]

Operation:

  m_prime = K-PKE.Decrypt(dkPKE,c)

  (K_prime,r_prime) = G(m_prime || h)

  K_bar = J(z || c)

  c_prime = K-PKE.Encrypt(ekPKE,m_prime,r_prime)

  mismatch = full_compare(c,c_prime)

  K =
    K_prime when mismatch == 0
    K_bar   when mismatch != 0

Output:
- K: exactly 32 bytes

Requirements:

- G and J are both executed for every decapsulation
- re-encryption is always executed
- all 1088 ciphertext bytes are compared
- no early exit
- mismatch location does not alter comparison loop length
- K selection uses a full-width mask
- implicit-reject flag is secret internal data
- implicit-reject flag is destroyed before termination
- no application-visible valid/invalid ciphertext indicator

--------------------------------------------------

bit-exactly equivalent to the required re-encode check.

After the checked ek is accepted:

  m <- 32 fresh random bytes

  ML-KEM.Encaps_internal(ek,m)

Public wrapper:
- requests exactly 32 fresh bytes
- handles entropy failure
- does not invoke Encaps_internal on a failed key check
- does not treat rho bytes as encoded coefficients
